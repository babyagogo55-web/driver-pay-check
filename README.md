# 運行日報・給与チェック（driver-pay-check）

トラックドライバー本人が毎日30秒で運行を記録し、月の総支給額（概算）と手当の内訳を自動集計して、会社の給与明細・運行内容手当明細と照合するスマホ用アプリ（PWA）。データは端末内（IndexedDB）にだけ保存し、外部に送らない。

- **公開中：https://babyagogo55-web.github.io/driver-pay-check/** （スマホで開いて「ホーム画面に追加」）
- 設計：[docs/design.md](docs/design.md)
- 本人向けの使い方：[docs/user-guide.md](docs/user-guide.md)
- 試作を渡すときの案内文：[docs/handout.md](docs/handout.md)

## セットアップ

Node.js 20 以上。

```sh
npm install
npm run dev       # 開発サーバー（同じWi-Fiのスマホから http://<MacのIP>:5173 で開ける）
npm test          # 計算ロジックのユニットテスト（Vitest）
npm run build     # dist/ に本番ファイルを出力
npm run preview   # 本番ファイルを手元で確認（オフライン動作はこちらで確認）
```

構成：

```
src/lib/        計算・照合・出力・音声解析の純粋関数（UIから独立）とテスト
  voice.ts      話した文 → 1日の記録（言った所だけ上書き）
  types.ts      データモデル
  calc.ts       日別・月別の計算
  reconcile.ts  会社明細との照合、日別金額の貼り付け読み取り
  report.ts     照合レポート文・CSV・リマインダー(.ics)
  dates.ts / money.ts / defaults.ts
src/db.ts       IndexedDB（記録・明細・設定、バックアップ）
src/store.tsx   画面共通の状態（変更は即保存）
src/screens/    記録・カレンダー・集計・照合・設定
public/sw.js    オフライン用 Service Worker
```

## 公開手順（無料）

スマホのホーム画面に追加するには HTTPS で公開する必要がある。どれか1つ。

### A. GitHub Pages（おすすめ・ワークフロー同梱）

1. GitHub に**非公開でも公開でもよい**リポジトリを作り、このフォルダを push（`main` ブランチ）
   - 注：無料プランで Pages を使うにはリポジトリを公開にする必要がある。コードに個人データは含まれない（データはスマホ内だけ）
2. リポジトリの Settings → Pages → Source を **GitHub Actions** にする
3. `main` に push すると `.github/workflows/deploy.yml` がテスト→ビルド→公開する
4. `https://<ユーザー名>.github.io/<リポジトリ名>/` をスマホで開き、ホーム画面に追加

`vite.config.ts` は `base: './'` なのでサブパスでもそのまま動く。

### B. Netlify / Vercel

ビルドコマンド `npm run build`、公開フォルダ `dist`。Netlify は `dist` フォルダをドラッグ＆ドロップするだけでも公開できる。

### 更新したとき

Service Worker は画面（HTML）をネット優先で取るので、次に開いたときに新しい版になる。部品（JS/CSS）はファイル名にハッシュが付くので古いものと混ざらない。`public/sw.js` を変えたときは `CACHE` の版名を上げる。

## データとプライバシー

- 保存先は端末のブラウザ内（IndexedDB）。サーバー・解析ツール・外部通信なし
- 例外1：Googleマップ連携（APIキーを設定した場合のみ）は、**営業所と行き先の住所・高速の有無**を Google の Routes API に送る。給与・点数・氏名は送らない。通信箇所は `src/maps.ts` だけ
- 例外2：「話して入力」はブラウザの音声認識を使うため、**音声**は端末の音声認識サービス（Google／Apple）に送られる。記録・金額は送らない。避けたい場合は「文字で入れる」
- 起動時に `navigator.storage.persist()` で自動削除されにくくするよう頼んでいる（許可されない端末もある）
- バックアップは JSON ファイル（`app: "driver-pay-check", schemaVersion: 1`）。本人が自分のドライブ等に保管する

## テスト

`npm test` で 119 件（計算・照合・出力・保存）。主な観点：

- 単価の適用開始日の前日／当日の切替、同じ月の中での値上げ
- 1日5箇所・複数荷物、単価未設定の警告、休みの日
- 距離：直接／メーター差、メーター逆転、小数単価（5.5円/km）、端数処理3種×日ごと／月合計
- 締め日：月末・20日締め・年またぎ・うるう年、基本給改定の適用時点
- 照合：一致・不足・過払い・会社のみ・自分のみ、期間外、日別比較の基準切替
- 日別金額の貼り付け（各種書式・全角・期間外・読めない行）
- 音声入力の解析：漢数字・助詞まじり・読み仮名・「280点5キロ」・メーター値・「2件目」・テンプレート＋言い直し・言った所だけ上書き・呼び名登録
- Googleマップ連携：道順（往復・片道・高速）、同じ道順の使い回しキー、送信内容に給与情報が入らないこと、応答の読み取り・エラー、距離の打ち間違い警告、拘束時間（日付またぎ）、APIキーをバックアップに入れないこと
- はじめの設定：初期値は金額が空、足りない設定の一覧、空でも計算が止まらないこと、使い始める前の日を未入力にしないこと
- CSVエスケープ、レポート文面、.ics、バックアップ検査、IndexedDB の保存・置き換え

## 既知の制約

- 決まった時刻の通知はサーバーなしでは出せないため、カレンダー登録用 .ics で代替（[設計書 §8](docs/design.md#8-記録忘れ防止通知の制約と代替策)）
- データは1台の端末内。別の端末へはバックアップファイルで移す
- 控除（税・社会保険）は手入力の概算のみ。計算はしない
