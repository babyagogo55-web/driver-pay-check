# 設計書：運行日報・給与チェック（driver-pay-check）

作成 2026-10-23。対象：運送会社に勤めるトラックドライバー本人（勤続20年以上）。

## 1. 課題の整理

| 現状 | 起きていること | このアプリでの解決 |
|---|---|---|
| 会社の運行内容手当明細は「1日＝1行の合計」だけ | どの行き先・荷物で何点・いくらかが本人に見えない | 自分の記録から日別・行き先別・荷物別の内訳を出す |
| 本人も細かく記録していない | 漏れ・誤りに気づいても根拠を示せない | 日々の記録が証拠になり、差額を根拠付きで示せる |
| 過去20数年で計算ミスが何度も（1万円不足、他人の売上1.8万円が混入、逆に本人の売上が他人へ） | 年1回程度の抜き打ちチェックでしか気づけない | 毎月、月合計と日別で自動照合し、差のある日を強調 |
| 記録は面倒だと続かない | 記録が止まった時点で価値ゼロ | テンプレート＋前回コピー＋自動保存で30秒以内 |

目的は会社を責めることではなく、**会社と従業員の双方にとって「綺麗でクリアな給料」**にすること。照合レポートの文面も中立（「会社の記載が少ない／多い」）にしている。過払い（プラスの差）も同じように出す。

## 2. ユーザー像

- 50代以上、勤続20年以上。仕事のパターンは何年もほぼ同じで、運賃の相場感はある
- 毎日トラックで出る。記録するのは1日の終わり、車内で片手
- 今は Googleカレンダーにざっくり記録しているだけ
- 夜間に複数の市場（1晩で最大5箇所以上）を回ることがある → 日付の区切り時刻を設定可能にした

## 3. 画面設計

下部タブで5画面。どの画面からも1タップで移動できる。

```
[記録] ─ 日付 ◀▶ ─ テンプレート/前回コピー/手入力/休み
   │        └ 行き先カード（行き先チップ・荷物ごと −[数]+・高速）×N
   │        └ 走行距離（直接 / メーター差）・メモ・この日の手当・警告
[カレンダー] 締め日で区切った1か月。✓記録済み／休／未（赤）／⚠要確認。タップ→記録
[集計]  総支給額（概算）・内訳・未入力日・警告・行き先別・荷物別・日別・控除→手取り目安・CSV/印刷
[照合]  明細の月合計入力→差額／日別入力（1件ずつ or 貼り付け）→差のある日を赤枠／
        日ごとの状況・メモ／月の状況／レポートのコピー・共有・CSV・印刷
[設定]  氏名・営業所／基本給（履歴）／距離単価（履歴）／行き先／荷物の種類／高速の扱い／
        単価表（改定日ごと）／締め日・支給日・端数・日付区切り・明細の日別の意味／
        テンプレート／記録忘れ防止／バックアップ
```

### 話して入力（音声で自動反映）

記録画面のいちばん上に「🎤 話して入力」。押して話し、話し終わると**自動で記録に反映**する（確認ボタンなし。「元に戻す」あり）。

- 例：「いつもの便A、太田垣 青果55、第一柿 ケース20、東日本 パレット4 高速、距離290キロ、メモ 渋滞で遅着」
- **言った所だけ上書き**：入力済みの日に「第一柿 ケース25」と言えば、その点数だけ変わる。テンプレート名を言えば呼び出してから直す
- 聞き取れなかった言葉は「これは？」と行き先・荷物の候補を出し、選ぶと**呼び名（別名）として覚える**。音声認識が固有名詞を毎回同じ字で間違える癖を、使うほど吸収する
- ブラウザの音声認識（Web Speech API）が使えない端末・許可がない場合は、入力欄＋キーボードのマイクで同じ解析をかける

### 30秒で終わる流れ（完了条件）

1. ホーム画面のアイコンを押す（今日の日付で開く）
2. 「いつものルート」ボタンを1回押す → 行き先・荷物・点数・距離が入る
3. 違う点数だけ −/＋ かテンキーで直す
4. 距離を直す（テンプレートの距離が入っている）
5. 終わり（保存ボタンはない。入力のたびに自動保存）

## 4. データモデル

`src/lib/types.ts` が正。要点：

| データ | 保存先（IndexedDB） | 内容 |
|---|---|---|
| Master（設定） | `kv['master']` | 基本給・距離単価（適用開始日つき履歴）、行き先、荷物種別、単価表、締め日、端数、テンプレート等 |
| DailyRecord | `records`（キー＝日付） | 休みフラグ、行き先（Stop）の配列、走行距離、メモ |
| Stop | DailyRecord内 | 行き先ID、荷物（種別ID×点数）の配列、高速利用 |
| UnitPrice | Master内 | 行き先ID × 荷物種別ID × 適用開始日 → 1点あたり円 |
| Statement | `statements`（キー＝支給対象月） | 会社明細の写し（月合計4項目、日別金額）、日ごとの照合状況、月の状況、控除 |

設計上の判断：

- **単価は「行き先×荷物×適用開始日」の1行ずつ**。値上げは改定日を追加して変わった所だけ入れる。計算時は「その日以前で一番新しい適用開始日」の単価を使う。過去の記録は旧単価のまま正しく計算される
- **高速加算は単価表の特別な列（`__highway__`）**として扱う。高速の扱いが不明なため、「変わらない／行き先ごと加算」を切替可能にし、運行内容手当に含めるかも設定にした
- 行き先・荷物は削除せず「使わない」にする（過去の記録の計算を壊さない）
- IDは安定した文字列。将来、会社アプリのデータや他ドライバーのマスタと突き合わせるときの鍵になる

## 5. 計算仕様（`src/lib/calc.ts`）

単位を整数に揃えて**浮動小数点を一切使わない**：

- 金額：円の整数
- 距離：0.1km単位の整数（`km10`。280.5km → 2805）
- 距離単価：1/100円単位の整数（`rateX100`。5円/km → 500、5.5円/km → 550）

```
距離手当(日) = 端数処理( km10 × rateX100 ÷ 1000 )   … km10×rateX100 は 1/1000円単位
荷物の手当(日) = Σ 行き先ごと Σ 荷物ごと ( 点数 × その日の単価 )
高速加算(日)   = Σ 高速を使った行き先 ( その日の高速加算額 )   … 設定「行き先ごとに加算」のときだけ
運行内容手当(日) = 荷物の手当 ＋ (高速加算を運行内容手当に含める設定なら 高速加算)
総支給額(月) = 基本給(締め日時点で有効な額) ＋ 距離手当(月) ＋ 運行内容手当(月) ＋ (含めない設定の高速加算)
手取り目安 = 総支給額 − 控除（任意入力）
```

- 端数処理：切り捨て／四捨五入／切り上げ。処理タイミングは「1日ごと」か「月の合計で」を選べる（会社の計算方法が不明なため）
- 締め日：0＝月末締め、1〜28日締め。`N月分` ＝ 前月(N+1)日〜当月N日。年またぎ対応
- 夜間運行：「朝X時より前に開いたら前日の記録にする」設定（初期値は使わない）
- 単価未設定・距離未入力・メーター逆転・行き先未選択は**0円で計算し警告を出す**（黙って0円にしない）

## 6. 照合仕様（`src/lib/reconcile.ts`）

- 差額 ＝ **会社の金額 − 自分の記録**。マイナス＝少なく払われている疑い、プラス＝多い（他人の売上混入の疑い）
- 月合計：基本給・距離手当・運行内容手当・総支給額のうち、入力した項目だけ比べる
- 日別：比べる金額は設定で「運行内容手当だけ」か「距離手当も含む」
- 要確認（赤枠）にする日：
  1. 両方に金額があり一致しない
  2. 会社に記載があるのに自分の記録がない（他人の売上が入った疑い）
  3. 日別記載のある明細で、自分の記録（0円以外）があるのに会社の記載がない（自分の売上が他人へ行った疑い）
- 状況管理：未確認／一致／問い合わせ中／翌月加算予定／解決済み／自分の記録ミス（日ごと・月ごと＋メモ）
- 日別金額の一括貼り付け：`10/1 12,345`、`2026-10-01,12345`、`10月1日 12345円`、`1日 12345` 等。年・月は期間から補う
- 出力：テキスト（コピー／LINE・メール共有）、CSV（1明細1行、BOM付きでExcel可）、印刷・PDF

## 6-2. 音声入力の解析仕様（`src/lib/voice.ts`）

1. 正規化：全角→半角、カタカナ→ひらがな、漢数字→数字（二百八十→280）、「（仮）」等の注記除去、「280点5キロ」→280.5km
2. 単語に分ける：行き先名・荷物名・それぞれの呼び名・テンプレート名・キーワード（高速／高速なし／距離／出発・帰着メーター／休み）を長い順に当てる。数字は直後の単位で「km」「点数」「〜件目（無視）」を区別
3. 組み立て：行き先が出るたびに新しい行き先。荷物の直後（または直前）の数をその荷物の点数に。「メモ」から後ろは言ったままメモへ
4. 反映：同じ行き先があればその荷物の点数だけ置き換え、なければ追加。行き先を言わずに荷物だけ言ったら、その荷物を持つ行き先が1つならそこを直す。荷物の種類を言わずに数だけなら、その行き先の荷物が1種類ならそれ
5. 言い直し・呼び名登録は「反映前の記録」からやり直す（二重に足されない）

プライバシー：ブラウザの音声認識は、音声を端末の音声認識サービス（Android＝Google、iPhone＝Apple）に送って文字にする。アプリ自身は記録・金額をどこにも送らない。音声も送りたくない場合は「文字で入れる」を使う。

## 6-3. Googleマップ連携（距離・運転時間の目安）（`src/lib/route.ts`・`src/maps.ts`）

**位置づけ**：距離手当の正は**メーター（会社の計算）**。地図の距離は ①距離を入れ忘れた日の目安（ワンタップ／設定で自動入力）、②入力した距離の打ち間違いチェック、③照合時の根拠（記録に「地図の目安」を残す）に使う。地図の距離を手当の計算に直接使わないのは、寄り道・迂回・会社の距離基準と一致する保証がないため。

| 段階 | 必要なもの | できること |
|---|---|---|
| A. キーなし（全員） | 営業所と行き先の住所 | 「Googleマップでルートを見る」で、その日の道順（営業所→行き先→営業所）をGoogleマップで開く。距離・時間はマップの画面で見る |
| B. キーあり（自動） | 上記＋Routes API のキー | その日の道順の**距離と運転時間を自動で表示**、距離が空なら自動入力（設定）、入力した距離と15%以上違えば警告 |

仕組み：

- 道順 ＝ 営業所 → 行き先（記録の順）→ 営業所（往復は設定）。住所文字列のまま Routes API `computeRoutes` に渡す（`address` 指定。経由地は25か所まで、11か所以上は料金区分が上がる）
- 高速：1回の依頼で区間ごとの高速指定はできないため、**1か所でも高速なら高速あり**、なければ `avoidHighways`
- 料金を抑える工夫：`TRAFFIC_UNAWARE`（渋滞考慮なし）、返してもらう項目は `distanceMeters,duration` だけ、**同じ道順は端末に覚えて二度と問い合わせない**（キー＝住所の並び＋高速の有無。点数が変わっても同じ道順）。毎日ほぼ同じルートなので、問い合わせは月に数回程度の見込み
- 送る内容は**営業所・行き先の住所と高速の有無だけ**（テストで点数・金額・氏名が入らないことを確認）。アプリが外へ通信するのはこの1か所（`src/maps.ts`）
- ブラウザから直接呼べることを実測で確認（2026-10-23、CORS プリフライトに `access-control-allow-origin` が返る）。サーバーは不要
- APIキーは端末にだけ保存し、**バックアップファイルには入れない**。キーは「ウェブサイト制限＝公開URL」「API制限＝Routes APIのみ」で作る（盗まれても他所では使えない）
- 料金（2026-10 時点の公開情報）：2025年3月から月$200のクレジットが廃止され、機能ごとの無料枠になった。Compute Routes の基本区分は月10,000回まで無料とされる（第三者の料金解説による。Google公式の料金表で要再確認）。個人の利用はこの範囲に収まる見込み

**出発・帰着の時刻**：記録に任意の出発・帰着時刻を追加（音声「出発21時半、帰着5時」も可）。日付またぎを考慮して拘束時間を出し、月の合計を集計に表示、CSVにも出す。給与計算には使わない（証拠・労務の記録用）。

**検討して見送ったもの**：Googleマップの「タイムライン」（実際に走った経路の履歴）から自動で行き先・距離を拾う案。タイムラインは2024〜2025年に端末内保存へ移り、Webからは読めない。書き出しファイル経由なら可能性はあるため、将来拡張に回した。

## 7. 技術選定の根拠

| 選択 | 理由 |
|---|---|
| PWA（Vite + React + TypeScript） | iPhone/Android 両対応、App Store不要、無料配布、ホーム画面に追加できる |
| IndexedDB（端末内保存） | 給与は個人情報。サーバーに送らない。オフラインでも記録できる |
| 自前の Service Worker（`public/sw.js`） | 依存を増やさず、仕組みが読める大きさに保つ。画面はネット優先、部品はキャッシュ優先 |
| 計算は純粋関数＋Vitest | 給与計算は間違いが許されない。UIと切り離して網羅テスト（113件） |
| 静的ホスティング（GitHub Pages 等） | 無料。サーバー処理がないので漏えいする受け皿もない |

## 8. 記録忘れ防止（通知の制約と代替策）

- ホーム画面に置いたWebアプリは、**サーバーなしでは「決まった時刻に通知」を出せない**（iPhoneはiOS 16.4以降でWebプッシュ自体は可能だが、送信用サーバーが必要。端末内だけで時刻予約する仕組み〔Notification Triggers〕は標準化されなかった）
- 代替策（実装済み）：
  1. 設定画面から**毎日の通知つき予定（.ics）**を作り、スマホ標準カレンダーに登録
  2. 記録画面を開くと「今月まだ記録していない日がN日」と表示 → カレンダーへ
  3. カレンダーで未入力日を赤表示
- 他の手：スマホの目覚ましに「日報」と名前を付ける／iPhoneのショートカットの「オートメーション」で毎日決まった時刻にアプリを開く

## 9. 将来拡張（今回は設計で考慮のみ）

| 拡張 | 今の作りで備えていること |
|---|---|
| 同じ営業所の他ドライバーへ展開 | 設定（Master）は1つのJSON。バックアップの `master` 部分だけを配布・取り込みする機能を足せば単価表を共有できる。行き先・荷物IDを揃えておけば照合結果も比べられる |
| Googleカレンダーからの過去記録取り込み | 記録は日付キー。カレンダーの予定タイトルを行き先名と照合して下書きを作る取り込み画面を足す（個人データのため取り込みは端末内で） |
| 伝票・運行明細書の写真読み取り | 1日分の記録（行き先×荷物×点数）を作るだけの入口を足す。計算・照合はそのまま使える |
| 会社の新アプリとの照合 | 会社アプリのカレンダーに日別売上が出るなら、それを照合画面の「まとめて貼り付け」へ。書式がわかれば専用の読み取りを足す。会社アプリへの自動連携は会社の許可と仕様が必要 |
| Googleマップのタイムラインから自動記録 | 端末からの書き出しファイル（JSON）を取り込み、行き先の住所と訪問地点を照合して記録の下書きを作る。書式の確認が必要 |
| 複数端末・家族のPCで見る | 今はバックアップファイルで移す。同期が必要になったら暗号化したうえで本人のGoogleドライブに置く方式を検討 |
